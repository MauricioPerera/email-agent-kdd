# Seguridad y privacidad

- Las credenciales se resuelven en memoria y no deben aparecer en logs, commits, nodos OKF ni mensajes del agente.
- El formulario local guarda contraseñas únicamente en el almacén seguro nativo del sistema: Windows Credential Manager, macOS Keychain (vía `security`) o Linux Secret Service/libsecret (vía `secret-tool`, que requiere una sesión de escritorio con el daemon activo). Si el almacén de la plataforma no está disponible, el alta se detiene con un aviso claro que nombra el almacén que falta: no existe alternativa menos segura ni respaldo en texto plano ni en variables de entorno.
- IMAP se abre en modo de solo lectura y el cursor evita duplicados.
- El envío es una operación externa y requiere la frase exacta `CONFIRMAR ENVIO`.
- Un resultado SMTP incierto no se reintenta automáticamente.
- Las notificaciones se evalúan localmente y se deduplican por hash del mensaje.
- El registro de inicio automático (`startup install`) serializa la línea de comandos sin ejecutar una shell y sin interpolar datos sin escape: Windows construye el valor de `/TR` de `schtasks` con `subprocess.list2cmdline` (una ruta con espacios, comillas o contrabarra final no parte el comando), macOS escribe cada valor del plist escapado con reglas XML (markup en la ruta no rompe el XML ni agrega claves) y Linux cita cada argumento de `ExecStart` con el escapado de systemd (`\\`, `\"`, `%%`, sin expansión de especificadores). Los caracteres de control en la raíz se rechazan antes de escribir cualquier archivo: un salto de línea no puede inyectar directivas nuevas en la unidad.
- La emisión de notificaciones de escritorio nunca invoca una shell ni interpola el asunto del correo en un script: Windows ejecuta un script de PowerShell constante vía `-EncodedCommand` y recibe el texto por variables de entorno; macOS usa un AppleScript constante con `system attribute`; Linux lo pasa a `notify-send` como argumento tras `--`. Un asunto con comillas, `$()`, backticks o saltos de línea se muestra como texto y jamás se interpreta como código. El fallo del mecanismo nativo se informa con un error genérico, sin detalles ni datos del correo, y el mensaje fallido no se marca como enviado (se reintenta en el ciclo siguiente).
- Reporta vulnerabilidades sin incluir contraseñas, tokens, archivos de correo o datos personales.
- El alta de cuentas (formulario GUI y asistente de terminal) jamás imprime contraseñas, `credential_ref` ni secretos: los mensajes de error son genéricos y no incluyen tracebacks.
- Cancelar el alta, cerrar el formulario o abortar por un error no persiste nada: sin escritura de cuentas ni de servidores.
- El asistente de terminal nunca pide la contraseña: solo el nombre de la variable de entorno que la contiene.
- La comprobación previa IMAP/SMTP solo autentica; nunca descarga ni envía mensajes, y un fallo se informa con un mensaje genérico.
- La desvinculación (`account remove ROOT ACCOUNT_ID CONFIRMAR DESVINCULAR`) exige la frase literal, que escribe el usuario, y es transaccional: borra la referencia de la cuenta en `accounts.json` y su configuración pública de servidores en `mail-servers.json`, y solo cuando todo lo local quedó limpio borra el secreto del almacén nativo de la plataforma (Credential Manager en Windows, Keychain en macOS, Secret Service en Linux). Si un paso falla, se restaura el estado local previo (rollback best-effort) y el error original se propaga: nunca queda un secreto huérfano silenciosamente ni se reescriben secretos. El secreto jamás se resuelve ni se lee durante la desvinculación; la salida no incluye `credential_ref` ni secretos, y los correos ya descargados se conservan byte a byte.
- Los instaladores de `installers/` comprueban el comando `email-agent --help` antes de declarar éxito y no imprimen ni piden secretos.
